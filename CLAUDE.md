# Interior AI Editor

## Что это за проект

Веб-редактор для дизайнеров интерьера и производителей материалов:
сканируешь комнату (или используешь примитив на этапе MVP) → получаешь
интерактивную 3D-модель → кликаешь на поверхность (стена, пол) →
описываешь материал текстом ("тёмный дубовый паркет") → AI генерирует и
накладывает seamless-текстуру прямо на выбранную 3D-поверхность.

**Ключевое отличие от конкурентов** (RoomGPT, Interior AI, ReimagineHome):
те перерисовывают всё фото целиком заново (плоская 2D image-to-image
генерация). Мы работаем с реальной 3D-геометрией — комнату можно
покрутить, менять материал точечно на конкретной поверхности без
перегенерации всей сцены.

Полная архитектура и обоснование решений — в `docs/architecture.md`
(соответствует `interior-ai-editor-overview.md`).

## Текущий приоритет (MVP)

**Сейчас в работе — только это, в таком порядке:**
1. ✅ Куб-примитив в Three.js (4 стены + пол, orbit controls, базовый свет)
2. ✅ Текстовый промпт → Stable Diffusion → seamless-текстура
3. ✅ Клик на поверхность (raycasting) → применение текстуры на неё
4. 🔶 Убедиться, что текстура накладывается бесшовно и выглядит убедительно
   — базовый seam-fix есть (см. "Прогресс"), но можно ещё улучшить

Реальная 3D-реконструкция комнаты (сканирование через Polycam/KIRI),
маркерная геометрия, сегментация окон/дверей, свой AR SDK — **не трогать
на этом этапе**, это следующие шаги после того, как петля выше полностью
работает end-to-end.

## Прогресс

**2026-09-01 — MVP-цикл 1-3 пройден end-to-end:**

- `frontend/`: Vite + React + TS + Three.js настроен. `Scene.tsx` —
  комната (пол + 3 стены, передняя сторона открыта под камеру), orbit
  controls, свет (`DirectionalLight` + `AmbientLight` — direction-only
  давал чёрные грани). `three/createRoom.ts` — геометрия, у каждой стены
  свой экземпляр материала (важно: если материал шарить между мешами,
  текстура одной стены "утекает" на все остальные). `PromptForm.tsx` —
  форма промпта, вынесена отдельным presentational-компонентом.
- Raycasting по клику определяет, на какую поверхность накладывать
  текстуру (`targetMaterialRef`, дефолт — пол, до первого клика).
- `backend/`: Express + TS, роут `POST /api/generate-texture` →
  `ai-service/generateTexture.ts` дёргает локальный SD API
  (`tiling: true` + `", seamless texture, tileable"` в промпте,
  1024×1024) → результат прогоняется через
  `ai-service/makeSeamless.ts` (свой алгоритм: сдвиг квадрантов на
  половину размера + маскированное размытие шва по кресту, через
  `sharp`) → base64 на фронт.
- Stable Diffusion (Forge) поднят локально на этой машине
  (`127.0.0.1:7860`, `--api`), conda-окружение `sdforge` с Python 3.10.6
  (Forge требует именно 3.10.x, конфликтует с более новым Python).
  Модель `juggernautXL_ragnarok.safetensors` уже стоит.
- Известный нюанс sharp: `.removeAlpha().joinChannel(...)` в одной
  цепочке не срабатывает как надо (альфа-канал не подхватывается) —
  нужно материализовать `.removeAlpha()` в отдельный `.toBuffer()`
  перед `joinChannel`.

**2026-09-16 — Toolbar доведён до полностью рабочего состояния (кнопки
Select/Move/Reset), плюс два бага полировки (зум, растягивание текстур).**

- **Select и Move теперь взаимоисключающие инструменты** (как в
  Photoshop, активен только один), а не независимые тумблеры — заведено
  через единый `activeTool: "select" | "move"` (state) +
  `activeToolRef` (синхронизированный ref, нужен потому что обработчики
  клика/наведения объявлены внутри `useEffect` с пустыми deps и не видят
  свежий React state напрямую — classic stale closure).
  - **Select** (дефолт) — обычное поведение: hover-подсветка + клик
    выбирает поверхность. Выключение (переключение на Move) **сбрасывает
    текущий выбор** (`selectedRef`/`targetMaterialRef` в `null`, прячет
    `selectionOutline`, закрывает Generate-панель) — так по явному
    запросу пользователя, не тихая деталь.
  - **Move** — `OrbitControls.mouseButtons` переключаются на лету:
    в Select ЛКМ = ROTATE, ПКМ = PAN; в Move — наоборот (ЛКМ = PAN,
    ПКМ = ROTATE). Нужен отдельный `controlsRef`, т.к. `controls`
    создаётся внутри того же `useEffect` со scene-сетапом.
  - **Reset material** — просто `material.map = null` + `needsUpdate`:
    `material.color` никогда не трогается при наложении текстуры, так что
    сброс карты сам по себе возвращает дефолтный цвет, без нужды хранить
    "исходный" материал отдельно.
- **Кастомный zoom колёсиком** — встроенный dolly-zoom OrbitControls
  мультипликативный (каждое деление колеса домножает дистанцию на
  коэффициент), из-за чего шаг зума ощутимо уменьшается по мере
  приближения к цели. `controls.enableZoom = false` + свой `wheel`-хендлер,
  двигающий камеру вдоль `camera.getWorldDirection()` на константный шаг
  (с `minDistance`/`maxDistance` клампом) — даёт равномерный зум.
- **Фикс растягивания текстур на стенах.** Причина: пол квадратный
  (10×10), стены — нет (10×3), а `texture.repeat` был захардкожен
  `(3, 3)` для любой поверхности; на стене это давало тайлы 3.33:1
  вместо квадратных. Фикс — `repeat` считается от реальных размеров
  поверхности (`geometry.parameters.width/height`, доступны у
  `PlaneGeometry` из момента создания) делённых на константу `tileSize`
  (сейчас `2`, метров на один тайл). Из-за этого `applyTextureToMaterial`
  стала принимать `mesh` вместо голого `material` — геометрия нужна
  только через mesh.
- **Побочная деталь окружения (не код):** Forge не запускался с ошибкой
  `ImportError: DLL load failed ... Политика управления приложениями
  заблокировала этот файл` — это Windows 11 **Smart App Control**
  (`HKLM\SYSTEM\CurrentControlSet\Control\CI\Policy
  VerifiedAndReputablePolicyState = 1`), блокирующий неподписанные
  `.pyd`/DLL по всей системе, а не Mark-of-the-Web конкретного файла
  (`Unblock-File` тут бесполезен). Выключается только вручную:
  Параметры → Конфиденциальность и безопасность → Безопасность Windows →
  Управление приложениями и браузером → Smart App Control → Выкл
  (необратимо без переустановки Windows — так предупреждает сама ОС).

## Стек

- **Frontend:** React + Vite + Three.js — TypeScript/JavaScript
- **Backend:** Node.js + Express — TypeScript/JavaScript
- **AI-генерация текстур:** Stable Diffusion (AUTOMATIC1111/Forge,
  self-hosted) — Python, API поверх WebUI (`--api` флаг), эндпоинт
  `/sdapi/v1/txt2img`, локальный адрес (например `http://127.0.0.1:7860`)
- **3D-реконструкция (пост-куб):** готовое API — Polycam или KIRI Engine.
  Масштаб и ориентация — через ARKit/ARCore/LiDAR телефона, БЕЗ физических
  fiducial-маркеров (это отброшенный вариант, не предлагать его снова)
- **Геометрия стен/поверхностей (пост-MVP):** Open3D, RANSAC — Python
- **Свой AR SDK (отдельный трек 5b, не блокирует MVP):** Swift (ARKit),
  Kotlin/Java (ARCore)

## Важные архитектурные решения (не пересматривать без явного запроса)

- **Fiducial markers (ArUco/AprilTag) — отброшены полностью.** Масштаб
  берётся из ARKit/ARCore/LiDAR или из готового API (Polycam/KIRI), которые
  уже это делают. Не предлагать физические маркеры как решение.
- **Определение окон/дверей — geometry-first, без цвета.** Цветовая
  сегментация отброшена (ломается от освещения/отражений). Подход:
  plane fitting (RANSAC) → дыры/аномалии в плоскости стены → кандидат на
  окно/дверь → опционально (пост-MVP) верификация готовой ML-моделью
  сегментации именно на вырезанном регионе, не на всей сцене.
- **Съёмка на MVP — обычная камера телефона**, без спец. приложения и без
  live AR-guidance. Live guidance через собственный ARKit/ARCore SDK —
  отдельный трек 5b, идёт параллельно без дедлайна, не блокирует MVP.
- **Backend — прокси/оркестратор**, не выполняет генерацию сам: принимает
  промпт от фронта, дергает локальный Stable Diffusion API, возвращает
  результат.

## Стиль работы с кодом

- Команда учится по ходу дела (JS/TS, Python, потенциально Swift/Kotlin
  для трека 5b) — комментировать код чуть подробнее обычного, объяснять
  нетривиальные решения (особенно в geometry/CV части на Python).
- Не мельчить архитектуру на тривиальные подзадачи, но и не собирать сразу
  полную "идеальную" версию — двигаться по зафиксированному MVP-порядку
  выше.
- При добавлении новых сегментов/фич — сверяться с `docs/architecture.md`,
  не переизобретать уже принятые решения заново.
